# 浏览器网申执行

先读根目录 `AGENTS.md` 和目标岗位的 `jobs/approved/*.json`。未找到有效批准清单，立即停止。`applications/<公司>_<岗位>/review.md` 必须显示 PDF 视觉与文本层验收通过；仅有 `manifest-draft.json` 不构成批准。

## 执行规则

1. 使用单个用户可见的 Chrome/Edge 会话；首次登录、扫码、验证码、短信验证和异地安全验证都交由用户完成。
2. 打开批准清单的 URL 后，核对域名、公司和岗位。发生非预期跨域、岗位已关闭、身份不一致或页面不可靠时停止并标记 `manual_required`。
3. 仅填写答案快照内的普通字段。填写姓名、电话、邮箱、教育、附件等个人资料属于向招聘网站传输敏感数据：在首次填写前，展示具体字段、目标网站和用途并取得即时确认。开放题可根据事实库草拟，但展示给用户确认后才能填写。敏感字段必须等待逐项用户确认。
4. 上传批准清单里哈希一致的附件。批准后不得重新渲染或编辑附件；若文件哈希变化，创建新版本并重新批准。网站只接受 DOC/DOCX 时使用已验收的同源 DOCX；文件类型不明确时停止。
5. 到达最终“提交/投递/确认申请”按钮时，展示公司、岗位、URL、附件、已填写字段摘要和缺失项，等待用户明确确认本次提交。
6. 用户确认后才点击一次。成功时保存脱敏确认页截图、回执号/成功文字和时间到 `applications/<公司>_<岗位>/receipt.md`，并将状态写为 `submitted`。
7. 未成功确认不能写 `submitted`。失败、退出或人为暂停必须记录当前位置并允许后续继续，不得重复提交。

## 禁止项

不得使用 stealth、验证码识别/破解、坐标猜测、多浏览器并发、批量绕过人工确认，或向平台发送未经批准的消息。
