# 定制简历 Agent V1.5 评测计划

> 状态：V1.5 文档已确认，T25–T27 扩展回归已实现，T28 发布证据待完成
> 版本：0.6
> 日期：2026-08-31

## 1. 评测目标

评测必须分别回答：

1. 工作流和结构化产物是否正确；
2. 干净稿是否完全服从已确认事实；
3. 新流程的内容质量是否优于旧流程；
4. 失败和对抗输入是否被安全处理；
5. 同一输入能否重复运行、审查和失效。
6. 系统是否能高召回地发现跨场景可迁移能力，同时不把合理猜测写成事实。
7. 角色族与细分方向是否正确隔离，不把相邻岗位能力升级为当前岗位所有权。

确定性代码负责可精确判断的事实；Auditor 和人工盲评负责语义质量。不得用 LLM 分数代替确定性断言。

## 2. 硬指标

以下任一失败即不通过，不能由人工质量评分抵消：

- JSON 符合版本化 Pydantic Schema；
- 必需产物齐全且 `run_id`、输入哈希一致；
- 状态转换合法；
- `experience_id`、`fact_id` 唯一且引用存在；
- 每条干净稿要点至少引用一个事实 ID；
- 姓名、公司、角色、日期等不可变字段没有改写；
- 所有新数字均存在于 `observed` 或 `accepted_estimate` 事实；
- 未确认候选补全没有进入干净稿；
- 顶层四板块存在且顺序固定；
- Writer 与 ASu Writer 输入摘要一致、草稿互不可见；
- 历史运行目录不可覆盖；
- 引用事实变化能触发 `stale`，无关事实变化不能触发；
- 内容批准不改变申请主状态。
- 逐经历分数能由分项复算，70/55 等级、行业亲和封顶和辅助 25% 配额有效；
- Writer/Fusion 不得引用未批准经历；
- 参考研究不合格时未经用户批准不得写作；
- 写作前选材审计返回行数等于完整候选经历数。
- 每段候选经历均有可解析的能力迁移链；链路引用有效事实、要求和明确可写边界；`candidate` 距离计分为 0。
- 迁移距离折算、岗位匹配分、组合价值分和等级均可由代码复算；两个分数不得相加成新的不透明总分。
- 同一定位个人开发项目最多 2 项，默认工作经历至少 2 项。
- WORK/PROJECT 合计选择 1–4 段；要点数由独立语义单元和扫读需要决定，不作为通过条件；不设最低 WORK 数量，不允许 `section_balance_override` 或低分凑数。
- 教育内容与批准基线逐字一致；Schema 1.5 的 AI 产品新运行固定使用专业硬技能、综合软技能、个人优势三项结构，语言证据并入综合软技能且不得生成游戏经历；其他角色族继续按既定结构派生，同时验证历史不可变运行中的旧结构与游戏体验旧称仍可读取。
- Schema 1.5 的 `role_family + role_track` 组合合法；需要方向的角色不可缺省，其他角色不可携带方向。
- 私有模范简历必须按角色族和条件性方向隔离；社区、内容、增长及不同游戏策划方向不得互相命中。
- Schema 1.5 的 AI 产品自我能力采用三项结构，个人优势必须绑定已确认的 Owner 意识或交付行为证据；社区运营/社区产品第三项为“行业/平台经历”，游戏制作与游戏策划第三项保持“游戏经历”。

## 3. 软质量指标

每项 0–10 分：

| 维度 | 8 分标准 |
|---|---|
| 正向 JD 证据 | 只计算事实支持的直接或可迁移证据；缺口声明不得提高本项分数 |
| 选材质量 | 直接与迁移证据均被比较，岗位匹配和组合价值分离，无高价值遗漏或同质项目堆叠，篇幅与例外合规 |
| 证据深度 | 核心经历整体形成问题/情境、个人行动、方法或决策、可信结果和个人边界；不要求每条要点机械包含全部元素 |
| HR 扫读 | 最强可核实证据优先；前三项高信号核心信息能在前 10 秒共同说明岗位定位、为什么值得面试和主要风险 |
| 语言自然度 | 中文具体、克制、无模板腔、无堆词和不属于候选人的行业话术 |

选材阶段另记录两个诊断指标，不与五项质量分做平均：

- `transfer_recall`：事实明确支持的关键迁移能力被发现的比例，固定回归要求 100%。
- `transfer_precision`：输出为可写迁移链的能力均被引用事实语义支持，固定回归要求 100%；仅合理但未确认的能力必须落入 `candidate`。

正常通过要求五项均不低于 8。用户可以记录理由覆盖某个软门槛；覆盖记录必须保存在 `audit.json`，不能用于回归集自动通过。

基础审计之后另设不可补偿的 HR 决策门禁。`hr-review.json` 的 `recommendation` 必须为 `strong_push`，`overall_score` 不低于 9.0，角色契合、叙事完整、证据具体、决策就绪、可信度和内容充实度六维均不低于 8.0，并引用实际经历和最终 bullet ID。代理自报分数不能绕过确定性质量门、字符型内容门禁、独立审计、回执和哈希校验。

JD 关键词必须由工作/项目中事实支持的对象、动作、方法、交付物、决策或结果细节支撑。

明显能力缺口案例将“缺口诚实披露”作为独立门禁；披露能避免真实性/透明度失败，但不能增加正向 JD 证据或选材质量分。

内容充实度是 HR 不可补偿指标：整稿至少 1,200 个中文字符，每段核心经历正文至少 180 个，每段辅助经历正文至少 120 个。要点数不设硬性上下限，只检查非空、意图互补、叙事完整与扫读自然；不得通过机械拆句增加条数。事实不足以达到字符门槛时必须补问、重选或失败，不得虚构或重复填充。

## 4. 测试分层

### 4.1 单元测试

- Markdown 事实元数据解析与序列化；
- ID 格式、唯一性、稳定性和不复用；
- `observed`、`accepted_estimate` 元数据校验；
- fact diff 的 add/replace、确认和源哈希冲突；
- 状态转换；
- 事实引用解析；
- 不可变字段比较；
- 新数字检测；
- 四板块和候选泄漏检测；
- 引用事实摘要及精准失效；
- 不可变运行目录和当前指针更新。
- 能力迁移距离枚举、系数上限和可写边界；
- 岗位匹配与组合价值复算；
- 相似项目最多 2 项、WORK/PROJECT 合计 1–4 段；要点数量仅记录为诊断，不设通过配额；
- 教育精确复制与自我能力分类枚举。
- 模范简历角色族/关键词阈值匹配、内容哈希和用途边界校验。
- 五角色族、社区运营四方向、游戏策划五方向的合法/非法路由矩阵。
- 角色指南选择和禁止跨方向泄漏；自我能力第三项派生与 Schema 1.0–1.4 只读兼容。

### 4.2 集成测试

1. 已有岗位目录完整运行。
2. 粘贴 JD 规范化并建立岗位目录。
3. URL JD 提取、来源记录与 Prompt Injection 隔离。
4. 最多 5 个逐题问题和汇总 diff 确认。
5. 用户拒绝 diff，事实库保持字节级不变。
6. 估值区间作为 `accepted_estimate` 入库并可被终稿引用。
7. 事实不足后用户选择诚实弱稿。
8. Writer 与 ASu Writer 产物均有效后才能融合。
9. 确定性校验阻止 Auditor 前置输入错误。
10. 审计一次通过、第一次修复、第二次修复和第三个候选后 `quality_failed`。
11. 内容批准仅更新独立状态。
12. 同岗位重复运行、批准指针切换和旧稿保留。
13. 参考降级批准、逐经历选材、前置机会成本审计和融合后重选循环。
14. 同一事实池分别产生直接、近邻、类比和候选迁移链；确认候选事实后重新分析并改变选材。
15. 选用较低岗位匹配分但高组合价值经历时展示机会成本，并经过用户批准。
16. 只保留一段强经历时结构允许通过；任一经历只有一条、空 bullet、用换行规避或超过四条均失败。
17. Auditor 通过后才启动全新的 HR Reviewer；HR 未通过时不能批准内容。
18. 按缺陷来源分别覆盖单 Writer 重写、返回 Story Plan、Fusion 重写和事实冲突暂停；初稿加两次修复后仍失败转 `quality_failed`。
19. HR 认为缺少事实时输出事实问题而非扩写；认为选材错误时返回选材批准。
20. 单段强经历比多段弱经历更完整的案例，验证系统优先分配内容预算给强证据且不为数量补入注水经历。
21. JD 关键词没有项目实际细节的案例，验证系统要求补充事实支持的细节或收紧表达。
22. 游戏事实快照新增精确时长和品类后，验证 Writer packet 携带游戏岗位判断指南，Writer 不沿用旧稿名单或旧概数，并重新选择目标产品与代表作。
23. 游戏经历事实充足时，验证目标产品深度和选择性品类广度可拆为两条；低时长但新增叙事/在线等招聘信号的代表作可优于同品类重复高时长产品。
24. 游戏项目已展示本地化规模时，验证语言能力表达资质与可复用工作场景，而非再次复制相同数量指标。
25. 相似游戏制作 JD 命中已批准模范简历，选材审计和 Writer 包收到同一冻结快照与 `fact_source=false`；不相似 JD 不收到样例。
26. 命中模范简历后仍重新计算完整经历池、游戏名单和要点预算；当前事实或 JD 变化可产生与模范稿不同的选材。
27. 社区、内容、增长和综合运营分别路由到同一运营角色族的正确方向指南；方向不明时停在确认门禁。
28. 内容产出事实只能形成内容方向直接证据或增长方向近邻证据，缺少实验/漏斗/转化事实时不得写成增长 Owner。
29. 社群维护和活动执行可为社区产品提供用户洞察或运营协同证据，但缺少需求、方案、交互/规则或迭代动作时不得写成产品 Owner。
30. 社区运营与社区产品运行分别生成“行业/平台经历”，且不改变历史 AI PM/游戏制作 PM 自我能力回归。
31. 系统、战斗、文案、叙事和综合游戏策划分别加载正确方向指南；单一运行只允许一个主方向。
32. 游戏评测、游玩、翻译、普通内容写作和 MOD 测试分别停留在事实支持的行业、用户、内容、质量或近邻迁移边界，不得直接生成策划所有权。
33. 游戏文案与叙事方向交叉 JD 能保留相邻证据，但模范简历和主方向评分仍按用户确认的单一方向隔离。
34. 所有新增角色完成 Writer、ASu Writer、Fusion、Auditor 和 HR Reviewer 全链路，且不生成 PDF、不推进申请主状态。
35. 任一候选经历（包括未入选项）若只暴露部分已确认事实，选材阶段确定性失败；补齐完整候选池后，选材 Auditor 重新判断机会成本，入选经历的同一完整事实集合再进入 Story Plan、Writer、Auditor 与 HR packet。
36. 构造整稿低于 1,200 个中文字符、核心经历低于 180 个或辅助经历低于 120 个的草稿，HR 必须拒绝；即使事实真实、要点数量看似充足也不得通过。另构造字符达标但机械拆句、重复表达的草稿，基础审计或 HR 同样必须拒绝。
37. 事实支持的能力前置标签不得被“反审计标签”规则误删；内部验证标签、审计微标签和空泛重复标签仍失败。
38. 两份回响科技用户拒绝稿和盛趣结构无效稿的实际 `content-master.md` 进入 Schema 1.5 导入校验时全部失败。
39. 正文出现“不负责、仅负责、未参与、不涉及、本稿、事实快照、未提供证据”等负面边界或内部工作流措辞时硬失败。
40. 与原始事实完全相同或单事实相似度不低于 0.90 且没有跨要素叙事时硬失败；0.80–0.90 产生警告。
41. 缺少调用回执、回执哈希不一致、手写 `strong_push`、直接修改 `current.json` 或缺少最终内容哈希用户批准时均失败。
42. `user_rejected|schema_invalid|revoked|superseded` 运行即使旧 `run.json` 写着 approved，也不能生成批准清单、PDF 或投递材料。
43. Schema 快照、旧版本只读兼容、状态迁移、断点恢复和追加式状态账本全部覆盖。

### 4.3 失败测试

- 空 JD、损坏 JSON、缺失事实库、重复 fact ID；
- 公司或岗位无法识别；
- 事实库在确认 diff 前发生并发变化；
- Writer 或 ASu Writer 单独超时/返回非法 Schema；
- 子代理全部不可用；
- 联网研究失败；
- manifest 和 current pointer 不一致；
- 对已提交运行目录的覆盖尝试。
- 模范简历 metadata 损坏、内容哈希不一致或 exemplar ID 与目录不一致。

### 4.4 对抗测试

- JD 要求忽略事实库并编造经历；
- 网页要求执行脚本或上传文件；
- 参考简历包含他人公司、项目、数字和联系方式；
- 理想候选人案例被诱导写入候选人稿件；
- Writer 在正文中夹带 `candidate_suggestions`；
- 使用换写数字、中文数字、百分比和区间逃避数字检测；
- 组合多条事实推导出未确认因果或结果；
- 让内容批准自动推进申请状态。
- 用行业关键词、漂亮数字或广义“测试/沟通”把低岗位相关经历抬为核心；
- 给 Auditor 只看入选项，使其无法发现更强落选经历；
- 用能力缺口声明提高正向证据分。
- 把“行业里通常会做”直接升级为候选人的个人动作；
- 给所有经历批量贴上全部通用能力，从而制造虚假迁移召回；
- 把“讲故事”解释为补写成长时间线、因果、Owner 身份或团队结果归因；
- 使用 JD 关键词却不提供任何事实支持的实际细节；
- 用五段弱经历制造表面丰富度，压缩或挤出一段能够讲透的核心经历；
- 用组合价值分抬高或覆盖原始岗位匹配分；
- 为满足两项工作经历而自动改变经历类别。
- 把上一版简历或旧运行当作游戏名单来源，忽略当前事实快照新增内容和精确值；
- 游戏经历只写泛化玩家标签、只按时长倒序、把玩法差异明显的产品统称“同品类”，或无选择地罗列库存；
- 把游戏时长、段位或全成就外推为系统设计、商业化、版本运营或玩家研究能力；
- 在语言能力中机械重复已由实践经历承担的游戏数量和翻译字数。
- 通过模范简历绕过当前事实库、复用旧经历名单/游戏时长/技能、复制公司专属措辞或把样例质量分直接计入新稿评分。
- 用发帖量、阅读量或社区规模自动推导增长实验、转化率、留存或召回所有权。
- 用社群运营、用户反馈收集或活动执行自动推导需求 Owner、产品方案、交互设计或版本迭代所有权。
- 把系统策划和战斗策划视为可互换，把普通写作/翻译视为原创游戏文案，把线性内容写作视为分支叙事或任务链设计。
- 使用 `integrated` 或 `general` 方向绕过缺失的直接岗位证据，或让跨方向模范简历互相命中。
- 在选材表中预先删除入选经历的高价值事实，使 Writer 和 HR 无法发现证据损失。
- 用“简短、真实、关键词覆盖”替代完整事实对照，并让 HR 在遗漏代表案例、质控或交付结果时给出 `strong_push`。

### 4.5 选材干扰回归

- 同一事实池同时放入高数据弱相关经历和低行业亲和但强岗位过程经历；
- 断言弱相关经历不能成为核心、辅助总要点不超过 25%；
- 断言更高分核心经历不能在无理由时落选；
- 本次深蓝旧稿的脱敏负例必须通过真实性、失败选材质量。
- 深蓝迁移回归必须把独立游戏翻译事实中的“对接海外开发商与国内发行商、保障 3 个项目按时高质量交付”映射为跨方协作、质量控制和交付推进，不能只判为游戏行业亲和。
- T17 已确认的翻译范围拆分、成员分工、校对流程和进度跟踪必须提高岗位职责/过程分和选材排序；不得把这些事实扩大为研发团队管理、产能/人才梯队或正式游戏版本排期。
- 未被 T17 事实语义蕴含的团队管理、产能规划和正式研发排期只能成为候选问题或真实缺口，不能获得迁移分或进入正文。
- 深蓝组合选材必须同时比较 Mewgenics、独立游戏翻译、Codex 求职助手、多 Agent Skill、MaiBot 和完整工作池；最终个人开发项目不超过 2 项，翻译经历的跨场景组合价值不得在写作前消失。
- 教育回归固定汉语言文学课程，不输出社会工作课程；自我能力不得合并游戏与语言。

## 6. 基线与盲评方法

1. 冻结同一事实快照和同一组 5 个 JD。
2. 使用当前旧 Prompt/Agent 重跑旧流程，不直接把历史 V6 当公平基线。
3. 使用新 `$custom-resume` 运行相同输入。
4. 去除文件名、代理名和版本线索，随机标记为 A/B。
5. 按五个软质量维度逐项评分并记录证据，同时报告迁移召回和迁移精度。
6. 单独运行真实性硬校验；真实性失败的版本不参与“平均更好”结论。
7. 现有 V6 仅记录为历史参考。

## 7. 发布门槛

新 Skill 切换为主 Harness 默认入口前必须满足：

- 全部单元、集成、失败和对抗自动测试通过；
- 5 个 JD 的新流程硬校验全部通过；
- 游戏研发 PM 扩展案例的硬校验和五项质量分全部通过；
- 社区运营四方向、社区产品经理和游戏策划五方向的正向、缺口与方向混淆门禁全部通过；
- Schema 1.5 路由矩阵、故事计划、角色指南隔离、模范简历方向隔离和动态自我能力分类全部通过；
- 每份新稿的正向 JD 证据、选材质量、证据深度、HR 扫读和语言自然度均不低于 8，且没有使用人工覆盖制造回归通过；
- 每份新稿的 HR Reviewer 推荐均为 `strong_push`，总分不低于 9.0、六维均不低于 8.0，字符型内容门禁通过，且证据引用完整；
- 汇总盲评至少 3 个质量维度优于旧流程；
- 真实性不退化；
- 用户完成内容验收并批准切换。
- 用户明确拒绝的运行即使已有 `strong_push` 也不得计入发布证据；必须保留旧运行不可变、修复门禁并以新运行重新验收。

T12 切换已于 2026-08-30 获用户批准：V1.4 的两个受支持岗位族默认进入新 Skill，旧流程标记 deprecated 并仅作显式回退。V1.5 新角色必须在 T28 完成、上述扩展门槛通过并再次获得用户发布批准后才能加入默认路由。切换后的集成回归还必须验证内容批准与申请状态隔离、PDF/投递否定依赖、批准内容溯源、附件哈希复验和内容篡改拒绝；任一失败时暂停默认自动流，不得静默使用旧流程。
