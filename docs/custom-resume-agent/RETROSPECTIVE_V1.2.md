# V1.2 能力迁移与组合选材复盘

> 日期：2026-08-24
> 结论：真实性通过，但内容验收失败；历史运行保持不可变且不批准。

## 1. 失败表现

- 独立游戏翻译已进入完整经历池，却只获得 52 分并在写作前被排除。
- 系统承认其游戏行业、跨方对接、量化产出和按期交付，但对项目协同、质量控制与交付推进的迁移价值给分过低。
- 多个个人开发项目在岗位匹配分上靠前，却造成实践板块定位重复；工作经历和能力多样性不足。
- 教育课程和自我能力仍允许 Writer 自由重组，未落实用户要求的固定展示结构。

## 2. 根因

V1.2 为修复“行业亲和替代岗位证据”，过度要求经历已经发生正式版本规划、研发排期、依赖管理和风险闭环。它没有把以下三类内容分开：

1. 事实明确支持的源动作；
2. 源动作可以证明的跨场景迁移能力；
3. 行业惯例上可能存在、但候选人尚未确认的具体流程。

结果是第二类被当成弱行业亲和，第三类又因真实性约束完全没有被转成高价值追问。写作前 Auditor 复用了同一判断框架，重复确认了偏置结果。

## 3. 修正原则

- 先发散、再收敛：完整枚举事实可以证明的直接、近邻和类比能力；潜在流程只进入事实问题。
- 双轴选材：岗位匹配和整份简历的组合价值分别计算、分别展示。
- 能力互补优先：同类个人开发项目最多 2 项，避免用不同项目重复证明相同能力。
- 板块平衡可审计：默认至少 2 项工作经历；确实不足时允许一次用户批准的低分工作例外，不抬分、最多 2 个要点。
- 固定内容基线：教育不按 JD 改写，自我能力拆分为专业硬技能、综合软技能、游戏体验和语言能力。

## 4. 独立游戏翻译的正确边界

现有事实足以支持：

- 海外开发商与国内发行商之间的跨方协作；
- 本地化内容质量控制和优化建议；
- 多项目交付推进与按期交付；
- 游戏内容、玩家体验和跨语言沟通。

现有事实尚不足以支持：

- 管理翻译团队；
- 负责人员分工或成员绩效；
- 使用特定台账、排期或验收工具；
- 承担正式游戏研发项目经理所有权。

这些潜在过程必须由系统主动提问；用户确认后才能写入事实库并提高对应分项。能力迁移可以改变选材优先级，但不能绕过事实确认。

## 5. 回归要求

- 固定事实下，翻译经历不得再被归为只有行业亲和。
- 跨方协作、质量控制和按期交付三类迁移能力的召回率必须为 100%。
- 未确认的人员分工、正式排期和工具不得进入可写迁移链或简历正文。
- 翻译经历必须和高分个人开发项目共同参与组合价值比较，不能只按原始总分截断。
- 旧稿继续作为“真实性通过、选材质量失败”的不可变负例。
