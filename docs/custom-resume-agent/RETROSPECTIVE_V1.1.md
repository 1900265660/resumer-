# 深蓝内容验收失败复盘（V1.1 → V1.2）

> 日期：2026-08-23
> 失败运行：`cr_20260822T094427_8ebd47`
> 处置：保留为不可变 `needs_content_review` 历史负例；不批准、不覆盖、不生成 PDF。

## 现象

旧稿虽然通过事实引用检查，却把独立游戏翻译、MOD 测试和独立游戏评测分配了 9/12 个经历要点。智联项目经理实习以外，招聘智能问答助手、Codex 求职助手、5G 项目、Mewgenics Demo 和多 Agent Skill 等更强产品/项目证据没有经过同一尺度的完整比较。

## 根因

1. 参考研究为空，岗位方法卡被当成了内容范式，缺少真实相邻岗位简历和官方生产岗位标准。
2. `EvidenceMapping.selected` 选择的是 JD 要求，不是经历；批准后全部映射事实进入 Writer，无法表达经历级取舍。
3. “游戏行业相关”被误当成“游戏项目管理相关”，没有区分行业亲和、可迁移动作和直接岗位动作。
4. 两个 Writer 看到同一个有偏输入，盲写只能提供表达差异，不能找回输入前已丢失的强经历。
5. 10–14 条和 1,200–1,500 字被错误使用为填充目标，弱经历为了凑密度进入正文。
6. Auditor 把诚实缺口声明计入 JD 覆盖，也没有比较落选强经历的机会成本，因此产生虚高质量分。
7. 旧游戏夹具没有同时放入“高数据弱岗位相关”和“低行业相关但强项目动作”干扰项。

## V1.2 修复映射

- 参考门禁：真实相邻岗位简历 + 官方岗位职责 + 脱敏选择规则；否则显式降级批准。
- 完整经历池分项评分：代码复算总分、70/55 阈值、行业亲和封顶 54、核心遗漏理由、辅助 25% 配额。
- 写作前独立机会成本审计：每个候选经历一行，先解决选材再启动 Writer。
- Writer/Fusion 硬隔离：只接收批准的工作/项目经历 ID 和逐经历要点上限；教育/技能作为固定非竞争基线。
- 融合后第二次机会成本审计：发现更换经历才能修复时返回 `reselect_required`，最多重选两轮。
- 质量拆分：正向 JD 证据、选材质量、证据深度、HR 扫读、语言自然度分别评分；缺口披露单独验收。
- 密度改为最大型软预算：不超过 14 个经历要点和 1,500 字，不设必须填满的下限。
- 新增干扰负例和旧稿错误模式测试；Schema 1.0 历史运行只读兼容，新运行使用 1.1。

## 回归期望

- 智联项目经理实习必须进入核心候选。
- 招聘问答助手、Mewgenics Demo、5G 项目、Codex 求职助手等必须参与完整评分。
- 游戏翻译、MOD 测试、评测不得判为核心，正文合计要点不超过 25%。
- 真实性通过但弱经历挤占强经历时，`selection_quality` 必须失败。
- 用户批准选材前不得启动 Writer；内容批准仍不得触发 PDF、投递或申请主状态。
