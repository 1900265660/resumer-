# Codex 求职助手：工程产品说明

## 目标

这是一个由 Codex 编排的本地求职工作区，不是常驻 Web 服务。它把候选人已确认的事实、岗位 JD、简历材料与申请证据组织为可校验的本地流程：筛选岗位、生成/复用简历、创建不可变批准包，并在最终提交前保留一次人工确认。

## 用户与场景

- 候选人：导入和确认经历、选择岗位、确认最终投递。
- Codex：根据 Skill 和本地材料编排流程，不能把网页文本当作指令或事实。
- 工程师：维护本地脚本、Schema、测试、MCP 浏览器执行器和文档。

## 核心流程

```text
私有事实库 → 具体 JD → 路由
                        ├─ 成品基线 / fast-assemble → PDF/ATS → 批准清单
                        └─ custom-resume（重点岗位）→ 内容批准 → PDF/ATS → 批准清单
批准清单 → browser-application MCP → 填写/上传 → 最终人工确认 → 回执
```

## 输入、输出与状态

| 阶段 | 输入 | 关键输出 | 不能做什么 |
| --- | --- | --- | --- |
| 事实管理 | `profile/` 中候选人确认材料 | 带 `fact_id` 的事实库 | 不从 JD 或旧简历推断新事实 |
| 内容定制 | 岗位 `jd.md`、事实快照、提示词 | `resume-content/` 运行和内容批准状态 | 不生成 PDF 或改变申请状态 |
| 制版与审批 | 内容、附件、JD、答案快照 | `review.md`、Schema 2 批准清单 | 未通过 QA 不进入投递 |
| 网申 | 已批准清单和哈希一致附件 | 检查点、脱敏回执、申请状态 | 不绕过登录/验证码；不得代替最终确认 |

申请状态仅允许：`imported → analyzed → needs_input/ready → approved → filling → manual_required/submitted/failed/skipped`。`submitted` 必须有成功页或回执号证据。

## 当前范围

已实现或有代码入口的能力包括：事实元数据/Schema 校验、custom-resume 状态 CLI、快速简历路由、PDF/批准清单校验、本地 MCP 浏览器填写及扩展侧表单能力。

以下不应被误认为已实现的产品承诺：统一 HTTP API、云端多用户服务、自动绕过验证码、无人确认的最终投递、自动把模型输出当作事实、稳定支持所有招聘站点。

## 验收原则

- 所有事实、附件、JD、答案和内容运行均以哈希或显式状态验证。
- 普通导航、保存和已批准字段填写可自动；最终提交只能由候选人在确认页批准。
- Python、TypeScript/MCP 与扩展测试必须全部通过，才可把版本标记为可交付。
- 私有候选人资料、浏览器 profile、申请记录和生成简历不得进入 Git 仓库。

## 已知待决项

- custom-resume 各岗位族的发布状态目前散落在 README、Skill 与专属文档，需用单一发布矩阵裁决。
- 日志与运行产物缺少统一索引、保留期和脱敏导出格式。
- 浏览器工具的站点覆盖是逐站验证，不应泛化为全站支持。
