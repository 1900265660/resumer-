# 优秀简历与历史版本对标结论

## 参考范围

- `优秀简历/`：7 个文件，包括 2 份 PDF、1 份 DOCX、3 张简历图片和 1 份校招顾问 Prompt。
- `最新汇总/`：20 份历史 PDF，覆盖编辑、运营、游戏策划、AI 产品等方向。
- 当前测试稿：`候选人_淘宝闪购_AI产品经理_定制简历.pdf`。

## 逐份参考结论

1. `打码 简历3.pdf`：黑白单栏、页首集中个人信息、细线分区；经历以动作和结果为主，不用卡片化装饰。
2. `许轩宁-华南理工大学-28届-每周五天-到岗时间七月中上旬-实习6个月及以上.pdf`：一级板块清楚且克制，依次为教育经历、实习经历、项目经历、个人简介；核心经历用 `[项目背景]`、`[工作职责]`、`[成果收获]` 组织，工作职责继续拆成用户调研、竞品分析、产品设计、数据处理、模型调优和效果优化等独立证据条。其价值不在于照搬长度，而在于每条都能回答“对应岗位哪项能力、用了什么方法、产生什么结果”。
3. `参考简历  222.docx`：咨询型黑白简历；每条经历同时交代项目规模、个人动作、使用方法和交付结果，例如团队人数、企业样本、访谈数量和报告页数。优点是证据完整，缺点是部分 Bullet 过长，不直接照搬其句长。
4. `内容运营.png`：用“业务背景—业务目标—工作内容—知识沉淀”呈现一段经历，并把直播运营、数据分析、内容宣发、门店协同拆开，说明复杂经历应按工作模块展开。
5. `内容运营2.png`：采用关键词前置的短 Bullet，把账号运营、内容设计、活动策划、转化和作品集分开；适合学习扫读层级，但不照搬模糊的自我评价。
6. `AI产品经理.jpg`：每个核心项目先写项目背景和职责边界，再按用户调研、竞品分析、产品设计、数据处理、模型评测、效果优化展开，最后单列成果；证明 AI 产品项目不能只写“用了什么技术”和一个结果。
7. `ai prompt.txt`：适合岗位适配、赛道调研和校招路线规划，不直接承担简历生成；其中“岗位门槛与加分项分开、给出竞争力缺口”的思路纳入 JD 分析阶段。

## 优秀简历的共同特征

1. 黑白或低饱和配色，分区用细线，不使用大面积蓝色标题和卡片条。
2. 姓名与求职意向集中在页首；照片位于右上角，不额外撑高首屏。
3. 信息密度高但层级稳定：公司/项目、角色、时间同一行，正文用短标签组织。
4. 经历不是“项目名称 + 技术词”，而是“背景/职责 → 关键动作 → 结果”。
5. 最强经历获得最多篇幅，次要经历快速收束；技能不重复项目正文。
6. 一页接近填满但保留自然页边距，没有下半页大面积留白。
7. 核心经历通常不是 2 条封顶，而是 4–6 条不同维度的证据；每条只承载一个主要卖点，避免把整个项目压进长复句。

## 权威职业中心规则

- Yale 建议用 `Action + Project + Result` 描述个人贡献，并用可验证的数量、比例或交付物说明影响：<https://ocs.yale.edu/resources/writing-impactful-resume-bullets/>。
- MIT 建议用 PAR（Project / Activity / Result）结构，把 JD 关键词放入真实语境；每条控制在 1–2 行，并用数据规模、团队规模或数据集大小体现复杂度：<https://capd.mit.edu/resources/resumes-writing-about-your-skills/>。
- Stanford 的 CAR 框架要求同时写清 Context、Accomplishments、Results，并强调信息量应由与岗位的相关程度决定：<https://careered.stanford.edu/sites/g/files/sbiybj22801/files/media/file/developing_your_resume_handout.pdf>。
- 对校招候选人仍优先一页，但“一页”是编辑目标，不是删除关键证据的理由；先形成完整内容母版，再压缩重复和弱相关信息。

## 可执行写作规则

1. 核心项目必须包含 1 句背景/目标和 4–6 条证据，至少覆盖“问题或需求、方案/流程、关键执行、评测/验证、结果/交付”中的四类。
2. 次要项目写 1–2 条，只保留与 JD 的 S/A 级要求直接相关的能力。
3. 每条 Bullet 以动作或能力标签开头，正文回答“做了什么、怎么做、为什么有价值”，目标为 1–2 行。
4. 有数字时说明口径；无数字时用交付物、流程复杂度、覆盖范围、迭代次数或协作对象证明价值，禁止编造指标。
5. 先产出不受页数限制的内容母版，再制作一页投递版；不得用“总 Bullet 不超过 10 条”这类硬限制提前砍掉核心项目。

## 当前稿不合格的原因

1. 视觉语言偏模板：大蓝标题、GitHub 图标、灰色圆角卡片和空证件照框抢占注意力。
2. 首屏浪费：照片预留框撑高页眉，姓名左侧信息与教育经历之间出现大块空白。
3. 层级过粗：每个项目都有灰色公司条和蓝色副标题，招聘者扫描时被装饰切断。
4. 内容过薄：强项目只有 1–2 个短 Bullet，没有呈现背景、职责、方法、交付和指标口径。
5. 求职说服力不足：看见了 Agent、Android、问卷和游戏，但不容易形成“为什么适合 AI 产品经理”的完整证据链。
6. 技能栏重复正文，缺少标杆简历中对角色、业务问题和结果的紧凑归纳。
